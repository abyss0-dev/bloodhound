# create-pr

変更の目的、設計判断、証拠を、レビューで検証できる形で PR に書く。
節の構成は `.github/pull_request_template.md` を唯一の拠り所とし、この skill には複製しない。

## 手順

1. **変更を把握する。**
   `git diff <default>...HEAD` と `git log <default>..HEAD` で、デフォルトブランチとの差分とコミットを読む。
   未コミットの変更があれば、PR に含めるべきかを利用者に確認する。
2. **`.github/pull_request_template.md` と `docs/philosophy/` を読む。**
3. **目的を一文で書く。**
   一文で書けない場合は、PR を作らずに分割を提案する。
4. **設計判断を取り出して書く。**
   構造に影響する判断だけを、何を決めたか、何を守るためか、その責任をどこが持つかの形で書く。
   作成者の意図が差分から読み取れない判断は、推測で埋めずに利用者に確認する。
5. **証拠を書く。**
   実際に実行して確認したテスト、計測、コマンドとその結果だけを書く。
   実行していないものを証拠として書かない。
   証拠がなければ、ないと書く。
6. **該当しない節は消す。**
   要件や公開契約を変える場合は、「人間の判断が必要な点」を必ず残す。
7. **PR を作成する。**
   ブランチを push し、`gh pr create --title "<タイトル>" --body-file <本文ファイル>` で作成する。
   作成した PR の URL を報告する。

## 守ること

* 差分の言い換え、試したことの経緯は書かない。
* 本文は判断の結論と根拠だけにし、自明なことは書かない。
* デフォルトブランチへ直接 push しない。
* PR の承認やマージは行わない。
