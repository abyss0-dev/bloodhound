# あるべき姿を宣言し、自律的に差分を収束させる（Declarative and Reconciliation）

目標とする**「あるべき最終状態（望ましい姿）」をデータとして定義し、現実の稼働状態との差分をシステム自身に自律的に解消させること**を設計の基本原則とする。

逐次的な手続きを1ステップずつ外部から指示するのではなく、目標状態を宣言し、そこへ向けて現実の状態を収束させ続ける機構を構築する。

## 手続き的な指示が抱える脆弱性

命令的な逐次スクリプトは、実行途中の通信エラーや外部からの手動変更によって、想定と現実のシステム状態に静かな乖離（ドリフト）を生じさせる脆弱性を持つ。
この乖離は検知されないまま潜在化し、突発的な障害を引き起こす要因となる。

一方、宣言的アプローチでは、目標状態（Desired State）をデータとして定義し、**「目標状態」と「現実状態」を継続的に比較して差分を自律的に解消する調停ループ（Reconciliation）**を稼働させる。
一時的な不整合や障害が発生した場合であっても、後続の調停サイクルが差分を検知し、自律的に目標状態へと収束させる。

## 本原則がもたらす特性

* **自律的な自己修復（Self-healing）**：一時的な障害、ネットワーク瞬断、コンポーネント再起動が発生しても、手動介入を要さずに自律的に目標状態へ復帰する。
* **状態乖離の可視化**：現実状態が宣言から外れた場合、その差分が即座に抽出されて可視化される。
* **安全な変更とロールバック**：変更は「目標状態の差分」として事前に評価可能であり、不具合時には宣言を旧状態へ戻すのみで自律的にロールバックが完了する。

## 適用原則

本原則は、外部データソースとの照合や長時間処理など、中断可能性を伴う処理に適用する。
ただし、調停機構の導入は [現在の確実性のレベル](design-at-current-certainty.md) に従い、中断やドリフトが不変条件を損なうことが判明している処理に限定する。

* **定期照合による自己修復（アンチエントロピー）**：リアルタイム通信における取りこぼし回復を手動手順とせず、外部の権威ある状態と内部状態を定期照合し、未反映差分を自律的に収束させる。
* **中断可能処理の自律的再開**：長時間処理において単一プロセスの継続生存を前提とせず、進行状況を復元可能とし、中断後も同一の目標状態へ収束可能な構造を採用する。

これらを実現する具体的機構は、対象システムの要件および実行基盤の制約に基づきアーキテクチャ設計で決定する。
